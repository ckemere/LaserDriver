# LaserHAT — working rules

Three KiCad 9 projects, all hand-placed and hand-routed by the user; scripts check, tidy and
sync, they do not rebuild:

| Project | Files | Fab |
|---|---|---|
| **LaserHAT** (Rev 2) | `LaserDriver.kicad_pro/.sch/.pcb`, sheets `mspm0_controller`, `usb_uart`, `bnc_daughter_io`; `LaserHAT.kicad_sym`, `Footprints.pretty`, `Footprints.3dshapes` | `fab/LaserHAT` |
| **LaserDaughter** (laser-diode module) | `LaserDaughter/` | `fab/LaserDaughter` |
| **EStimDaughter** (e-stim module) | `EStimDaughter/` — its schematic is generated by `EStimDaughter/gen_schematic.py` (+ `sch_*.py`, deterministic UUIDs), its parts list is `bom_EStimDaughter.csv`, its sims are `sim/` | `fab/EStimDaughter` |

`REV2_NOTES.md` is the design history, `estim_interface/ESTIM_MODULE_SPEC.md` the HAT↔module
contract (§7 = agreed firmware/pins, §8 = how sessions coordinate), `claude_memory/` the session
context (see its README).  JLC order archives live in `fab/orders/`.

## Editing

- **The HAT and laser schematics were hand-edited in KiCad; there is no generator for them.**
  Patch the `.kicad_sch` text (`tools/sexpr_patch.parse` for spans, see `tools/stamp_lcsc.py`);
  never round-trip them through kiutils 1.4.8 (it un-hides every `(hide yes)` field).
- **Never rebuild a board from scratch.**  Net or footprint changes: edit the schematic, then the
  user presses F8 in pcbnew, or `tools/pcb_sync.py board netlist --keep-tracks` (keeps placement
  and copper).  Check for KiCad lock files (`~*.lck`) before writing any board or schematic.
- PCB scripts run in the `kicad` venv / KiCad's bundled Python (`pcbnew`).  Collect, then
  `board.Remove()` at the end; compare items by `m_Uuid`; copy `VECTOR2I`s before editing;
  `pcbnew.FootprintLoad()` breaks after `LoadBoard()` — use `PCB_IO_KICAD_SEXPR().FootprintLoad`.
- Clean-up helpers (transactional, clearance-checked): `tools/track_tidy.py`, `tools/silk_declutter.py`,
  `tools/gnd_islands.py`, `tools/fill_zones.py` (refill before DRC), `tools/overlaps.py`;
  `tools/maze_io.py` + `tools/maze_route.py` for a single missing connection.
- DRC must run on a board next to its `.kicad_pro` (HAT rules: clearance 0.15, hole clearance 0.25).

## Schematic ↔ board links (F8 safety)

KiCad pairs a footprint with its symbol by `(path "/<symbol uuid>")` (sub-sheets:
`/<sheet uuid>/<symbol uuid>`).  A mismatch makes F8 delete the footprint and add a fresh one,
losing the hand placement.  After **any** scripted edit:
`tools/path_check.py board sch` → 0 mismatches, and `tools/sync_check.py board sch` (read-only F8:
parts, footprint ids, values, DNP, pad nets, paths) → 0 differences.

## Part numbers and fab outputs

- `tools/lcsc_parts.py` is the only source of LCSC codes for the HAT and laser module (the e-stim
  module keeps `bom_EStimDaughter.csv`); `tools/lcsc_catalog.json` holds LCSC's data per code
  (`tools/lcsc_verify.py --refresh`).
- `tools/stamp_lcsc.py` writes the `LCSC Part #` field (the one the user's Fabrication Toolkit
  reads), Description and Datasheet into every symbol and footprint and sets the flags:
  `NOT_FITTED` → symbol DNP + exclude-from-BOM; `HAND_FIT` → no part number, excluded from BOM
  and position files (JLC rejects any BOM designator missing from the CPL); `NON_PARTS` → excluded
  from both; machine-placed parts get the flags cleared.  Values are part numbers for LEDs and
  switches (JLC's matcher groups by Value); function names are silkscreen texts.
- **Before any fab claim, all three must be clean:** `tools/lcsc_verify.py` (every R/C/L Value vs
  LCSC's parameter table, every IC vs its MPN, size codes vs package, all three boards),
  `tools/sync_check.py`, `tools/path_check.py`.  The Fabrication Toolkit's exact BOM/CPL can be
  reproduced with its `plugins.process.ProcessManager` (`claude_memory/fab-bom-scheme.md`).
- `tools/jlc_fab.py [Board]` regenerates `fab/<Board>/` (gerbers, BOM, CPL, renders, README with
  the hand-fitted and DNP lists) and warns when a board field disagrees with the table.

## Rev 2 MCU pin map (U7 MSPM0G3507 RHB, rot −90)

| Pin | Port | Net | Function |
|---|---|---|---|
| 1, 2 | PA0, PA1 | I2C_SDA, I2C_SCL | I2C0 → Pi GPIO2/3 (OLED bonnet). Only fail-safe OD pins: keep here |
| 3 | NRST | GPIO23 net | reset ← Pi GPIO23 (J1.16), R3 47k / C3 10n, JP4 RTS_NRST |
| 6 / 32 | PA2 / VCORE | ROSC / VCORE | R4 100k 0.1 % / C4 |
| 7, 8, 9 | PA3–PA5 | — | spare |
| 10 | PA6 | DB_GPIO | J8.3 FAULT_n → **TIMA0_FAULT0** (hardware PWM kill); J8 pins 3/5 swapped 2026-09-29 |
| 11 | PA7 | DB_PWM_A | J8.5 EN, **TIMA0_CCP1** |
| 12, 13 | PA8, PA9 | PI_RXD, PI_TXD | **UART1** TX/RX ↔ Pi GPIO15/14 |
| 14, 15 | PA10, PA11 | MCU_UART_TX/RX | UART0 ↔ CH340N (BSL) — fixed |
| 16 | PA12 | DB_PWM_B | J8.4 CATH, **TIMA0_CCP3** (independent channel, not a complement) |
| 17 / 18 / 20 | PA13 / PA14 / PA16 | BUTTON4 / 2 / 3 | SW7 wheel roll / push / roll |
| 19 | PA15 | DB_DAC | J9.3 DAC0 (e-stim RELEASE) — fixed |
| 21 | PA17 | DB_ADC_A | J9.4 ADC1.2 (e-stim bit-banged I²C SDA; PA17 only muxes I2C1_SCL, so hardware I2C1 needs a pin move — see REV2_NOTES) |
| 22 | PA18 | BSL_INVOKE | SW6 (active **high**) — fixed |
| 23, 24 | PA19, PA20 | SWDIO, SWCLK | ← Pi GPIO25 / GPIO24 (swapped vs Rev 1) — fixed MCU side |
| 25 | PA21 | BUTTON1 | SW8 BACK |
| 26 | PA22 | DB_ADC_B | J9.5 ADC1.8 (e-stim bit-banged I²C SCL; no I2C function on PA22) |
| 27 | PA23 | BUTTON5 | SW9 FIRE |
| 28 | PA24 | LED_MCU | D7 |
| 29 / 30 / 31 | PA25 / PA26 / PA27 | MCU_STIM_OUT / MCU_STIM_IN / PI_TRIGGER | U8 → J7 (TIMG12) / J6 → U8 (TIMG8 capture) / ← Pi GPIO26 (TIMG7) |

- Buttons SW7/SW8/SW9 are **active low** (commons on GND, internal pull-ups); SW6 stays active high.
- PWM_A/B and FAULT must stay on one TIMA timer (shared timebase + hardware fault kill).
- Pi header vs Rev 1: SWD swapped (GPIO24 = SWCLK, GPIO25 = SWDIO); NRST ↔ MCU_POWER_EN swapped
  (GPIO23 = NRST, GPIO18 = MCU_POWER_EN); trigger is GPIO26 → PA27.  Flash Rev 2 with
  `make flash HAT_REV=2` (Firmware/Makefile.gcc; `Pi/power_cycle.py` reads LASERHAT_*_PIN).
- OLED bonnet (Adafruit 4567) runs only on 3.3 V and ties header pins 1/17 together itself.
- J8/J9 pad positions and pinout are frozen (module contract, spec §7).

## Schematic conventions (for any new symbols or wires)

- Passives show only Reference and Value (pin names/numbers hidden).
- Every connected pin gets a 5.08 mm wire stub before its label; `GlobalLabel` for signals that
  cross sheets, `LocalLabel` within a sheet; symbols ≥ 5 mm apart; decoupling caps spread, not stacked.
- Never give a symbol that has a footprint a new UUID.
- `.kicad_pcb` files take no comments and no `(pintype ...)` in pads.

## Signal names

`+LASER_V` boost-derived laser supply (5/12 V) · `+3V3` / `MSPM0_3V3` MCU rails · `DB_PWM_A/B`,
`DB_GPIO`, `DB_DAC`, `DB_ADC_A/B` module header lines · `MCU_STIM_OUT/IN` BNC path · `PI_TRIGGER`
Pi GPIO26 · `MCU_UART_TX/RX` CH340N · `PI_RXD/TXD` Pi UART · `SWCLK/SWDIO` · `I2C_SCL/SDA` (OLED).
